# Warden MCP v0.1.7

Status: patch release notes

## Highlights

- fixes a cross-workspace active-plan leakage path caused by unsafe workspace bootstrap fallback
- makes unsafe launch roots fail closed by default instead of silently reusing a shared fallback workspace
- adds workspace-ownership validation for imported plan metadata and returns explicit mismatch errors

## User-facing changes

As of `v0.1.7`, Warden is workspace-scoped first:

- local read and write operations stay bound to the current workspace root
- launching from an unsafe OS directory such as Windows `System32` now returns a workspace error unless `WARDEN_WORKSPACE_ROOT` is set
- the old shared home fallback remains available only when explicitly enabled with `WARDEN_ALLOW_UNSAFE_WORKSPACE_FALLBACK=1`
- cross-workspace imported plan metadata now fails with `WORKSPACE_PLAN_MISMATCH` instead of being accepted silently

For coding-agent clients, the recommended setup is:

- set `WARDEN_WORKSPACE_ROOT` to the repo root when the client supports environment variables
- call `get_agent_guide`, then `health_check`, then `get_status`
- carry the returned `plan_id` forward on later writes
