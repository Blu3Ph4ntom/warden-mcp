# Warden MCP v0.1.5

Status: patch release notes

## Highlights

- hardens `plan_path` handling for MCP clients that expand the default plan path from an unsafe OS directory
- ignores bogus absolute defaults such as `C:\Windows\System32\.agent\PLAN.md` and snaps them back to the active workspace plan path
- preserves the workspace-root fallback and `WARDEN_WORKSPACE_ROOT` override behavior from `0.1.4`

## User-facing fix

Some MCP clients appear to send an absolute `plan_path` derived from the server launch directory instead of a workspace-relative path.

As of `v0.1.5`, when `warden-mcp` receives an unsafe absolute default-looking path such as:

- `C:\Windows\System32\.agent\PLAN.md`

it treats that as a bogus client-expanded default and resolves it back to the active workspace plan path instead of trusting the OS-directory path.

This specifically hardens `get_status`, `health_check`, and other plan-loading flows against clients that launch from unsafe directories and also expand `plan_path` incorrectly.
