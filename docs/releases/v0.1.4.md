# Warden MCP v0.1.4

Status: patch release notes

## Highlights

- fixes unsafe MCP launch cwd handling such as Windows `System32`
- adds `WARDEN_WORKSPACE_ROOT` override support for clients that can pass environment variables
- falls back to `~/.warden-mcp/workspaces/default/.agent/PLAN.md` when no trustworthy project workspace is available
- keeps the Codex-compatible MCP startup fixes from `0.1.3`

## User-facing fix

Some MCP clients launch local servers from an OS directory instead of the actual project root.

As of `v0.1.4`, `warden-mcp` now resolves its workspace root like this:

1. use `WARDEN_WORKSPACE_ROOT` when explicitly provided
2. otherwise use the current working directory when it is trustworthy
3. otherwise fall back to `~/.warden-mcp/workspaces/default`

This prevents writes to locations like Windows `System32` while still keeping project-local plans as the preferred default when the workspace root is valid.
